# サンショウオウオカーニバル

**オウオ大増殖パニック** — バケツをタップして放流を防ぐ、30秒のブラウザゲーム。

Vite / TypeScript / Canvas 2D / Web Audio API。ランタイム外部ライブラリ・外部API・APIキー・外部フォントは使いません。

## 起動

Node.js 22.12以降（この環境では24.19.0）とnpmを使用します。

```sh
cd /workspace/sansho
npm ci
npm run dev
```

Viteの表示するアドレスをブラウザで開きます。開発サーバーはポート5173、本番ビルドの確認は `npm run build` → `npm run preview`（ポート4173）です。

```sh
npm run typecheck
npm test
npm run build
```

ブラウザ自動検証は、開発サーバーを別のターミナルで起動してから実行します。

```sh
npm run test:browser
```

既定では `/usr/bin/chromium` を使います。別環境では `CHROMIUM_PATH=/path/to/chromium npm run test:browser` を指定してください。`TEST_URL` で対象サーバーを変更できます。結果とスクリーンショットはGit対象外の `test-results/` に生成します。Playwrightのパッケージは開発・テスト専用です。

## 遊び方

- 「30秒、川を守る！」でスタート。落下するオレンジ色のバケツをタップ／クリック。
- キーボードではCanvasにフォーカスを当ててスペースキー。最も下にあるバケツを阻止します。
- 阻止は100点。連続成功5・10・15・20回で倍率が1.5・2・2.5・3倍になり、該当する成功から適用されます。
- 見逃すと現在のコンボが途切れます。最高コンボと得点は残り、30秒までプレイできます。
- パニック指数は混乱の演出用の値で、高得点とは別です。見逃しがない場合は0のままです。
- タブを離れると一時停止。復帰後に「つづける」で再開します。30秒は一時停止を除く実プレイ時間です。
- 終了後1.4秒のフィニッシュを経てリザルトへ。音量・ミュート・動き軽減・ベストスコアをブラウザに保存します。保存が禁止された環境でもプレイできます。

## 実装した機能

- タイトル、チュートリアル、難易度の5段階進行、二重加点防止、リトライ
- 最大78体のぷにぷに群れ、空間グリッドによる近隣衝突、最大140個の粒子
- 侵入後だけの世代経過、5段階の混乱、成功コンボの祝祭演出
- 団体旅行・巨大オウオ・研究員・バケツおじさん・フィーバー
- ユーザー操作で開始する合成音とBGM、ミュート・音量・動き軽減
- 結果による称号／コメント分岐、1080×1920 PNG保存、Web Share API、X投稿文、URLコピー
- ネイティブ画像共有非対応時の画像保存、Clipboard API非対応時の手動コピーフォールバック
- 4章の生物学解説と本文を確認した環境省の出典、1200×630 PNGのOGP

## 公開

静的ホスティングの**ドメイン直下**へ `dist/` を配置できます。公開URLを指定してビルドすると、OGP画像・canonical・og:urlが絶対URLになります。

```sh
PUBLIC_SITE_URL=https://your-game.example/ npm run build
```

`your-game.example` は自分の公開先に置き換えます。サブディレクトリ配信はこの構成では未対応です。SNS共有・クリップボードにはHTTPSを推奨します。結果画像にはアクセス中のゲームURLを埋め込みます。X投稿に画像は自動添付されないため、保存画像をユーザーが追加します。画像共有が対応していても、共有先アプリでの挙動はアプリ側に依存します。

OGP素材を描画コードから再生成する場合は、開発サーバー起動中に `npm run assets:ogp` を実行します。公開・GitHubへのpushは自動では行いません。

## 検証範囲と残る改善

Chromiumで実時間30秒のPCプレイ、390px／320px表示、タッチ判定、見逃しでの混乱、リトライ、一時停止、設定／ベスト保存、画像出力、学習画面を検証しています。詳細は `docs/VALIDATION.md`。

クラウドの各タスクは隔離されています。既存の `/workspace/sansho` を使い、明示的な依頼がない限りGit worktreeを作る必要はありません。公開したスナップショットにファイルが残っても、開発サーバープロセスは次のタスクで再起動してください。

## iPhone・iPadから遊ぶためのGitHub Pages配信

`npm run build:pages` で `.pages/` に公開用ファイルを生成します。こちらはJS・CSS・アイコンを1つのHTMLにまとめているため、`/sansho/` のようなサブパスにも配信できます。公開先が異なる場合は `STATIC_SITE_URL` に末尾 `/` 付きのHTTPS URLを指定します。

公開用の `gh-pages` ブランチへ `.pages/` の内容を配置後、GitHubの **Settings → Pages → Build and deployment** で **Deploy from a branch → gh-pages → / (root) → Save** を選択してください。非公開リポジトリのPages利用可否はGitHubの契約プランに依存します。公開設定の操作にはPages権限が必要で、リポジトリへのpush権限とは別です。ゲームサイトは公開URLを知る人が閲覧できますが、リポジトリの公開・非公開設定は変更しません。

`node scripts/test-standalone.mjs` で公開用HTMLのサブパス配信・追加の外部リクエストがないことを検証できます。PCのお試し用には `npm run build:standalone` が生成する `ouo-play.html` をブラウザで開けます。iOSではダウンロードHTMLを直接実行できないことがあるため、HTTPSの公開URLで遊んでください。
